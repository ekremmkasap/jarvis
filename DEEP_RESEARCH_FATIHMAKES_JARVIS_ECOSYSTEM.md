### ⚡ HATA RECOVERY & SELF-HEALING PATTERNS

#### **ReAct Pattern** — İşAraştırma Döngüsü

```
Cycle Structure:
┌─────────────────────┐
│   Thought/Reason    │ ← LLM reasoning
│   Action/Plan       │ ← What to do next
│   Observation       │ ← Tool result
│   (Repeat)          │
└─────────────────────┘

Advantages:
✅ Transparent reasoning (audit trail)
✅ Dynamic error recovery (observe failure → replan)
✅ Multi-step workflows (complex tasks)
✅ Human interpretable (whitebox)

Example:
Thought: I need to check the user's calendar to see if they're free.
Action: use_tool(name="calendar_check", params={"user_id": "123"})
Observation: User has a meeting from 2-3pm.
Thought: They're free after 3pm. I should suggest 3:30pm.
Action: send_message(text="Let's meet at 3:30pm")
```

---

#### **Self-Healing Architecture (2026 Best Practice)**

```
Error Flow:
┌─ Task Execution
│  └─ Error Detected
│     ├─ Error Type Analysis (network? logic? API?)
│     ├─ Root Cause Identification (LLM-assisted)
│     ├─ Recovery Strategy Selection
│     │  ├─ RETRY (exponential backoff)
│     │  ├─ FALLBACK (alternative tool)
│     │  ├─ REPLAN (different approach)
│     │  ├─ ESCALATE (human intervention)
│     │  └─ ABORT (graceful shutdown)
│     └─ Recovery Execution
└─ Logging (audit trail)

Safeguards:
├─ Circuit Breaker (fail fast if repeated failures)
├─ Exponential Backoff with Jitter (prevent thundering herd)
├─ Token Cost Limits (prevent runaway LLM calls)
├─ Timeout Enforcement (prevent hanging)
└─ Validation Gates (prevent invalid outputs)
```

---

#### **Plan-and-Execute Framework (Trusted Boundary)**

```
Simple, Effective Pattern:

Planning Phase (High Trust):
    Plan_LLM → Generate multi-step plan
               ↓
Execution Phase (Low Trust):
    FOR each step in plan:
        ├─ Validate step (syntax, tool exists)
        ├─ Execute step (tool call)
        ├─ Validate output (type, range, safety)
        ├─ Handle errors (replan if invalid)
        └─ Log result
                ↓
    Return aggregated results

Benefits:
✅ ~80 lines Python (simple)
✅ Clear separation of concerns
✅ Easy to debug (plan vs. execution)
✅ Safe by design (validation gates)
```
